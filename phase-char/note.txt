# SQL Server Notes

## Rules of Normal Forms

→ **1NF**  
→ **2NF**  
→ **3NF**

### Primary Key

- Business Key
- Non-Business Key

---

## Referential Actions

- **NO ACTION** → Delete with my code
- **CASCADE** → Delete all related records
- **SET NULL** → Set the related foreign-key values to `NULL`
- **SET DEFAULT** → Set the related foreign-key values to their default value

---

## SQL Query Clauses

### Query Processing Order

**FROM → WHERE → GROUP BY → HAVING → SELECT → ORDER BY → TOP**

### WHERE / LIKE

`LIKE` is used when the data does not exactly match the specified value.

### LIKE Wildcards

- `%` → Matches zero or more characters.
- `_` → Matches exactly one character.
- `[abc]` → Matches one character from the specified set.
- `[a-z]` → Matches one character within the specified range.
- `[^abc]` → Matches one character that is not in the specified set.

---

## SELECT

```sql
SELECT
    TOP (n)
    DISTINCT selected_items
FROM table_name;
```

### DISTINCT

`DISTINCT` is used to select unique result rows and remove duplicate values from the result.

---

## ORDER BY

```sql
ORDER BY column_name ASC;
ORDER BY column_name DESC;
```

- **ASC** → Ascending order
- **DESC** → Descending order

---

## CASE Expression

```sql
CASE
    WHEN condition THEN result
    WHEN condition THEN result
    ELSE result
END AS category_name
```

`CASE` is used to return different values based on conditions.

---

## OFFSET / FETCH

```sql
ORDER BY column_name
OFFSET skipped_number ROWS
FETCH NEXT n ROWS ONLY;
```

- **OFFSET** → Number of rows to skip.
- **FETCH NEXT** → Number of rows to return.

This is commonly used for pagination.

# JOINs

## INNER JOIN

Returns matching records from both tables.

```sql
SELECT *
FROM TableA
INNER JOIN TableB
    ON TableA.ID = TableB.ID;
```

---

## OUTER JOIN

Outer joins include:

- **LEFT OUTER JOIN**
- **RIGHT OUTER JOIN**
- **FULL OUTER JOIN**

### LEFT OUTER JOIN

Returns all records from the left table and matching records from the right table.

### RIGHT OUTER JOIN

Returns all records from the right table and matching records from the left table.

### FULL OUTER JOIN

Returns all records from both tables, including non-matching records.

---

## Multiple JOINs

Multiple tables can be joined together in a single query.

```sql
SELECT *
FROM TableA
INNER JOIN TableB
    ON TableA.ID = TableB.A_ID
INNER JOIN TableC
    ON TableB.ID = TableC.B_ID;
```

---

## CROSS JOIN

Returns the Cartesian product of two tables.

```sql
SELECT *
FROM TableA
CROSS JOIN TableB;
```

# Subqueries

## Inner Query / Subquery

A query can be placed inside another query.

```sql
SELECT *
FROM TableA
WHERE ID IN
(
    SELECT ID
    FROM TableB
);
```

- **Inner Query** → The query inside.
- **Outer Query** → The main query that contains the inner query.

---

## EXISTS

`EXISTS` checks whether a subquery returns any rows.

```sql
WHERE EXISTS
(
    SELECT 1
    FROM TableB
    WHERE TableB.ID = TableA.ID
);
```

`EXISTS` can be useful when checking for the existence of related records, especially with correlated subqueries.

# Data Manipulation

## INSERT

Inserts new records into a table.

```sql
INSERT INTO table_name (field_name)
VALUES (value);
```

Multiple values:

```sql
INSERT INTO table_name (field1, field2)
VALUES
    (value1, value2),
    (value3, value4);
```

---

## CREATE TABLE

Creates a new table.

```sql
CREATE TABLE database_name.schema_name.table_name
(
    field_name data_type
);
```

Example:

```sql
CREATE TABLE dbo.Users
(
    UserID INT,
    UserName VARCHAR(100)
);
```

---

## DROP TABLE

Deletes the table object.

```sql
DROP TABLE IF EXISTS table_name;
```

---

## DELETE

Deletes selected rows from a table.

```sql
DELETE FROM table_name
WHERE filter;
```

Without `WHERE`, all rows can be deleted.

---

## TRUNCATE TABLE

Deletes all rows from a table.

```sql
TRUNCATE TABLE table_name;
```

It is generally faster and uses less logging than deleting rows individually.

---

## UPDATE

Changes existing data in a table.

```sql
UPDATE table_name
SET field_name = new_value
WHERE filter;
```

---

## MERGE

Can be used to perform different actions, such as inserting and updating data, based on a matching condition.

```sql
MERGE INTO target_table AS Target
USING source_table AS Source
ON Target.ID = Source.ID
WHEN MATCHED THEN
    UPDATE SET Target.Name = Source.Name
WHEN NOT MATCHED THEN
    INSERT (ID, Name)
    VALUES (Source.ID, Source.Name);
```

---

# OUTPUT

`OUTPUT` can be used to return information about rows affected by `INSERT`, `UPDATE`, `DELETE`, and `MERGE`.

```sql
OUTPUT INSERTED.*
```

```sql
OUTPUT DELETED.*
```

The `OUTPUT` clause can be useful for logging or retrieving affected data.

# SEQUENCE

A `SEQUENCE` is a database object used to generate sequential numbers.

```sql
CREATE SEQUENCE sequence_name
AS data_type
START WITH constant
INCREMENT BY constant
MINVALUE constant
MAXVALUE constant
CYCLE;
```

Options include:

```text
CYCLE
NO CYCLE

CACHE
NO CACHE
```

Example:

```sql
CREATE SEQUENCE OrderSequence
AS INT
START WITH 1
INCREMENT BY 1
MINVALUE 1
MAXVALUE 100000
NO CYCLE
CACHE 10;
```

# Keys

## Primary Key

A Primary Key:

- Uniquely identifies each row.
- Cannot contain `NULL`.
- Does not allow duplicate values.

```sql
PRIMARY KEY
```

---

## Foreign Key

A Foreign Key references a key in another table.

```sql
FOREIGN KEY
```

It is used to establish relationships between tables.

---

# Derived Tables

A derived table is a subquery used in the `FROM` clause.

```sql
SELECT *
FROM
(
    SELECT *
    FROM table_name
) AS DerivedTable;
```

---

# CTE — Common Table Expression

A CTE is a temporary named result set that can be referenced by the statement that follows it.

```sql
WITH CTEName AS
(
    SELECT *
    FROM table_name
)
SELECT *
FROM CTEName;
```

CTEs can also be recursive and can be useful for hierarchical data.

---

# Views

A View is a database object that stores a query definition and can be queried like a table.

### CREATE VIEW

```sql
CREATE VIEW view_name AS
(
    SELECT ...
);
```

Example:

```sql
CREATE VIEW ActiveUsers AS
SELECT *
FROM Users
WHERE IsActive = 1;
```

### ALTER VIEW

```sql
ALTER VIEW view_name AS
(
    SELECT ...
);
```

---

## WITH ENCRYPTION

`WITH ENCRYPTION` can be used with a view to encrypt its definition.

```sql
ALTER VIEW view_name
WITH ENCRYPTION
AS
SELECT ...;
```

---

## WITH SCHEMABINDING

`WITH SCHEMABINDING` binds the view to the underlying objects and prevents changes that would invalidate the view.

```sql
ALTER VIEW view_name
WITH SCHEMABINDING
AS
SELECT ...
FROM dbo.TableName;
```

---

## WITH CHECK OPTION

`WITH CHECK OPTION` can be used to ensure that modifications made through a view satisfy the view's filtering conditions.

```sql
CREATE VIEW view_name AS
SELECT *
FROM table_name
WHERE condition
WITH CHECK OPTION;
```

---

# ORDER BY in Table Expressions

`ORDER BY` generally cannot be used inside a view, CTE, derived table, or subquery unless it is used with an allowed construct such as `TOP` or `OFFSET/FETCH`.

```sql
SELECT TOP (10)
    *
FROM table_name
ORDER BY column_name;
```
